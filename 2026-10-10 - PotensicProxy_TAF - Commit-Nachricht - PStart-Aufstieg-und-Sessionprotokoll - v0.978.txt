BL_Improve PStart ascent and session logging

Date: 2026-10-10

Summary:
- Made the first PStart air-reference stage more robust by averaging the stable hover height, using a stronger close-range throttle command, accepting target crossing instead of exact decimetre locking, and settling vertical motion inside a tolerance band without commanding descent.
- Added configurable horizontal GPS warning and abort radii. Position drift inside the warning radius no longer blocks height stages; the abort radius must be exceeded continuously for one second before aborting.
- Added a 5 Hz per-session JSONL protocol with telemetry, PStart control commands, state transitions, image events, quality information, and explicit completion/abort status.
- Store PStart images and the JSONL sidecar in a session-specific Pictures/PotensicProxy/Recognition/PStart_<SessionId> directory when Android scoped storage permits it.
- Made the first STEP0 zero-zoom image the session master and embed the finalized gzip-compressed JSONL protocol in chunked JPEG APP15 segments. Master-image embedding is attempted independently so the protocol can still be preserved if Android rejects the JSONL sidecar.
- Extended PStart image XMP metadata with stage, height error, GPS/position quality, configured tolerance limits, PStart throttle command, and session/master/protocol references.
- Updated PStart settings, translations, application version to 0.978, and project documentation.

Validation:
- Vue/TypeScript check: passed with node node_modules/vue-tsc/bin/vue-tsc.js --noEmit.
- Kotlin parser/syntax scan: no parser errors; Android/project symbols are unresolved without the Android Gradle classpath.
- JPEG APP15 protocol container: tested with a real 1280x720 PStart JPEG; image remained decodable after embedding.
- Full Vite bundle: environment blocked because the delivered node_modules lacks @rollup/rollup-linux-x64-gnu.
- Android Gradle compile: environment blocked because the Gradle wrapper attempts to download Gradle 8.11.1 while network access is unavailable.
- Flight/hardware validation remains required for throttle values, wind behaviour, GPS tolerance, and Android scoped-storage sidecar placement.
